1. MuJoCo 로봇 로딩 및 MINK IK 이상 동작 디버깅
-------------------------------------------------

[사용자 요청]
이 폴더에 jdcobot200이라는 MuJoCo XML이 있는데, 이 로봇을 MuJoCo에
로딩하고 MINK IK를 적용하려고 합니다. 로봇이 이상하게 동작하므로 코드를
살펴보고 디버깅해 달라고 요청했습니다.

[분석 결과]
- 시작하자마자 graspframe을 [0, 0, 0.06] m로 보내고 있었습니다.
- 이 목표는 베이스 내부에 가까워 실질적으로 도달하기 어려운 위치였습니다.
- XML 관절 제한은 ±pi였지만 actuator ctrlrange는 이보다 좁았습니다.
- MINK가 actuator 범위 밖의 관절 자세를 계산할 수 있었습니다.
- IK 반복마다 전체 제어 주기 dt를 사용하여 명령 속도가 반복 횟수만큼
  증가하고 있었습니다.
- 제어 주기는 10 ms였지만 MuJoCo 물리 스텝은 한 번에 2 ms만 진행했습니다.
- DH 예제는 position actuator에 목표 각도가 아닌 토크형 PD 값을 입력했습니다.

[수정 내용]
- 안전한 초기 동작을 위해 현재 자세를 초기 IK 목표로 사용했습니다.
- 팔 관절 제한을 actuator ctrlrange와 동일하게 맞췄습니다.
- MINK ConfigurationLimit과 VelocityLimit을 적용했습니다.
- IK 반복을 제어 주기 내부의 서브스텝으로 처리했습니다.
- 10 ms 제어 주기당 2 ms MuJoCo 물리 스텝을 5회 진행하도록 했습니다.
- 도달 불가능한 목표에서 QP 예외로 프로그램이 종료되지 않고 마지막 안전
  자세를 유지하도록 했습니다.
- 최종 actuator 명령을 허용 범위 안으로 제한했습니다.
- DH 예제에서 position actuator에 목표 관절각을 직접 전달하도록 수정했습니다.

[검증 결과]
- 초기 자세 유지 오차: 약 0.004 mm
- 목표 [0.2, 0, 0.3] m 추종 오차: 약 0.079 mm
- 도달 불가능한 [0, 0, 0.06] m 목표에서는 관절 제한에서 안전하게 정지
- 모든 actuator 명령이 설정된 범위 안에 있음을 확인

[관련 파일]
- jdcobot200.xml
- jdcobot200_mink_solver.py
- jdcobot200_mujoco_glfw.py
- dh_param_fk_ik_MUJOCO.py

[실행 명령]
python3 jdcobot200_mujoco_glfw.py


2. 엔드이펙터 적색 마크 위치 수정
----------------------------------

[사용자 요청]
jdcobot200.xml에서 엔드이펙터 역할을 하는 적색 마크가 로봇 중심축에서
떨어져 있으므로 수정해 달라고 요청했습니다.

[분석 결과]
- 기존 graspframe의 로컬 위치는 [0.03, -0.02, -0.03] m였습니다.
- 그리퍼의 공구 중심축은 gripper_assembly의 로컬 z축입니다.
- 기존 마크는 중심축에서 x 방향 30 mm, y 방향 20 mm 벗어나 있었습니다.
- 핑거 메시 끝단은 로컬 z 약 -80 mm 지점에 있었습니다.

[수정 내용]
graspframe 사이트를 양쪽 핑거 끝 사이의 중심축으로 이동했습니다.

수정된 XML:
<site name="graspframe" pos="0 0 -0.08" size="0.006" rgba="1 0 0 1"/>

[검증 결과]
- 중심축 방사 방향 편차: 사실상 0 mm
- 수정된 graspframe 기준 MINK IK 오차: 약 0.011 mm


3. 그리퍼가 닫힌 상태로 시작하도록 변경
------------------------------------------

[사용자 요청]
시뮬레이터가 그리퍼를 닫은 상태로 시작하도록 요청했습니다.

[수정 내용]
jdcobot200_mujoco_glfw.py 초기화 시 gripper actuator에 GRIPPER_OPEN 대신
GRIPPER_CLOSED 값을 입력하도록 변경했습니다.

초기 제어값:
GRIPPER_CLOSED = 0.00

[검증 결과]
- Python 문법 검사 통과
- 실행 후에도 터미널에서 다음 명령으로 그리퍼를 제어할 수 있습니다.
  gripper open
  gripper close


4. 로봇 작업 가능 범위 분석 스크립트 작성
-------------------------------------------

[사용자 요청]
시뮬레이터 안에서 로봇이 동작 가능한 범위를 찾아내는 별도 Python 코드를
요청했습니다.

[생성 파일]
jdcobot200_workspace.py

[기능]
- 실제 XML의 관절 제한과 actuator 제한의 교집합을 사용합니다.
- 영점 자세, 모든 관절 한계 조합, 무작위 관절 자세를 샘플링합니다.
- 각 관절 자세에서 MuJoCo 순운동학으로 graspframe 좌표를 계산합니다.
- X/Y/Z 범위와 수평 최대 반경을 출력합니다.
- 관절 자세와 엔드이펙터 좌표를 압축 NPZ 파일로 저장합니다.
- 작업공간을 3D PNG 그림으로 저장합니다.
- 선택적으로 CSV 파일을 생성합니다.

[기본 실행]
python3 jdcobot200_workspace.py

[CSV 포함 실행 예]
python3 jdcobot200_workspace.py --samples 200000 --csv jdcobot200_workspace.csv

[기본 생성 파일]
- jdcobot200_workspace.npz
- jdcobot200_workspace.png

[5,000개 샘플 검증 결과]
- X 범위: -0.3985 ~ +0.4055 m
- Y 범위: -0.3984 ~ +0.3943 m
- Z 범위: -0.1791 ~ +0.5231 m
- 수평 최대 반경: 약 0.4076 m

[주의 사항]
현재 XML에서는 collision이 비활성화되어 있으므로 계산 결과는 자기충돌과
바닥 충돌을 제외한 관절 제한 기준의 기구학적 작업공간입니다.


5. X/Y/Z 최대 좌표 자세 시뮬레이션 스크립트 작성
---------------------------------------------------

[사용자 요청]
각 좌표별 최대값으로 로봇암을 시뮬레이터에서 동작시키는 별도 코드를
요청했습니다.

[생성 파일]
jdcobot200_axis_max_demo.py

[기능]
- MuJoCo 모델에서 X, Y, Z의 양의 최대 도달 자세를 각각 탐색합니다.
- 무작위 작업공간 샘플링으로 초기 후보를 찾습니다.
- SciPy가 설치된 경우 제한조건 최적화로 극값을 정밀 보정합니다.
- position actuator를 사용하여 각 자세 사이를 부드럽게 이동합니다.
- 그리퍼는 닫힌 상태를 유지합니다.
- wrist_roll은 위치 극값에 영향을 주지 않으므로 중립값을 유지합니다.

[동작 순서]
HOME -> X MAX -> Y MAX -> Z MAX -> 반복

[계산된 최대 좌표]
- X MAX: [0.4079, 0.0000, 0.1152] m
- Y MAX: [0.0000, 0.4079, 0.1152] m
- Z MAX: [-0.0017, 0.0000, 0.5231] m

[기본 실행]
python3 jdcobot200_axis_max_demo.py

[한 사이클 실행 후 종료]
python3 jdcobot200_axis_max_demo.py --once

[시간과 샘플 수 지정]
python3 jdcobot200_axis_max_demo.py --move-time 5 --hold-time 2 --samples 200000
