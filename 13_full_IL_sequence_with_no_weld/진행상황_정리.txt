1. 작업 목표
-----------

MuJoCo에서 block을 gripper에 weld로 강제 부착하지 않고, 실제 finger pad와
block 사이의 contact를 기준으로 다음 전체 imitation-learning 파이프라인을
구현하는 것이 목표이다.

  1) MuJoCo 시연 데이터 획득
  2) LeRobot v3 데이터셋 변환
  3) LeRobot ACT policy 학습
  4) 학습 checkpoint를 사용한 MuJoCo closed-loop 추론


2. 구현된 주요 파일
-------------------

README.md
  - 환경 구성과 전체 실행 방법 설명
  - 데이터 생성, 검증, 학습, 추론 명령 정리
  - contact grasp 구현 원칙과 제한사항 설명

scene.xml
  - JDCobot200, 작업대, red block, front camera 구성
  - red block과 gripper 사이의 weld equality 제거
  - block, floor, finger pad의 contact mask 분리

jdcobot200.xml
  - 로봇 MJCF와 actuator 설정
  - left_finger_pad와 right_finger_pad collision geom 구성
  - gripper actuator force와 position-control 설정 보완
  - 좌우 finger joint의 기계적 연동 equality 유지

jdcobot200_mink_solver.py
  - Cartesian 목표를 arm joint command로 변환하는 differential IK solver

generate_synthetic_trajectories.py
  - randomized pick-and-place expert trajectory 생성
  - 양쪽 finger pad와 block의 실제 MuJoCo contact 검사
  - joint limit, finite value, floor clearance, self-collision 검사
  - bilateral contact grasp와 object lift 여부 검사
  - 목표 위치의 최종 block placement error 검사
  - 검증을 통과한 episode만 NPZ로 저장
  - manifest.json에 성공 여부와 검증 결과 저장

create_lerobot_dataset.py
  - trajectory 생성과 LeRobot 변환을 연속 실행
  - 기본 50 Hz 제어, frame stride 5 사용 시 10 Hz 데이터셋 생성

convert_to_lerobot.py
  - NPZ trajectory를 LeRobot v3 형식으로 변환
  - observation.state: arm 5축 + gripper 1축
  - action: arm command 5축 + gripper command 1축
  - observation.images.front: front RGB camera
  - observation.images.wrist: wrist RGB camera
  - 각 episode의 영상을 인코딩하고 parquet/meta 파일 생성

validate_lerobot_dataset.py
  - LeRobot v3 metadata, feature shape, dtype, FPS 검사
  - parquet header/footer와 camera video 검사
  - LeRobotDataset public loader로 실제 sample decode 검사
  - state/action/image의 shape, dtype, finite value 검사

lerobot_act_compat.py
  - 현재 LeRobot 환경에서 ACT 관련 모듈만 안정적으로 import하기 위한 호환 코드

train_lerobot_act.py
  - local LeRobot dataset을 사용하는 ACT policy 학습
  - CPU, CUDA, MPS device 선택 지원
  - optimizer, action chunk, logging, 중간/final checkpoint 저장
  - policy preprocessor와 postprocessor도 checkpoint에 함께 저장

infer_lerobot_act_mujoco.py
  - ACT checkpoint를 로드해 MuJoCo에서 closed-loop 추론
  - 학습과 동일한 front/wrist image 및 joint state 생성
  - policy action을 arm/gripper actuator에 적용
  - 거리만으로 block을 붙이지 않고 bilateral contact를 확인해 grasp 판정
  - 최종 위치, 목표 오차, 접촉 frame, grasp/release step을 JSON으로 저장

run_full_pipeline.sh
  - 데이터 생성, 검증, ACT 학습, 추론을 순서대로 실행
  - 첫 번째 인자: episode 수
  - 두 번째 인자: 학습 step 수


3. weld 제거 상태
-----------------

scene.xml에는 red block을 gripper에 연결하는 weld가 존재하지 않는다.
Python 코드에서도 red_block_grasp equality를 찾거나 eq_active를 변경하지 않는다.

MuJoCo 모델의 neq 값은 1이다. 이 equality는 block weld가 아니라 실제 gripper의
left/right finger joint가 서로 반대 방향으로 움직이게 하는 기구 연동용 joint
equality이다.

검증 결과:

  XML OK: nq=14, ngeom=32, neq=1; no block weld


4. contact grasp 방식
--------------------

grasp는 다음 조건으로 시작한다.

  - left_finger_pad가 red_block_geom과 접촉
  - right_finger_pad가 red_block_geom과 접촉
  - gripper close command가 설정된 threshold 이하
  - 추론 시 bilateral contact가 지정된 frame 수만큼 확인됨

MuJoCo contact만으로 작은 로봇/물체 조합에서 발생하는 수치적 미끄러짐을 줄이기
위해, contact가 실제로 성립한 후 compliant spring-damper grip force를 사용한다.

  - block pose를 순간이동하지 않음
  - equality 또는 weld를 사용하지 않음
  - block pose를 rigid하게 고정하지 않음
  - 최대 적용 force: 3 N
  - 위치 spring gain: 180
  - velocity damping gain: 4
  - gripper open 단계에서 즉시 해제

즉, 실제 양쪽 finger contact가 grasp 시작 조건이며, 이후 물체에는 제한된
compliant force가 적용된다. manifest와 inference report에는 다음 필드가 기록된다.

  uses_weld: false
  contact_conditioned_compliant_grip: true


5. 시연 데이터 구성
-------------------

각 NPZ episode에는 다음 배열이 포함된다.

  timestamp
  qpos
  qvel
  action
  ee_position
  block_position
  block_quaternion
  desired_ee_position
  phase
  left_finger_contact
  right_finger_contact
  grasp_contact_force

기본 trajectory phase:

  start
  pre_pick_waypoint
  pick_hover
  pick_descend
  grasp_close
  lift
  carry_waypoint
  goal_hover
  goal_align_1
  goal_align_2
  place_descend
  place_correct_1
  place_correct_2
  release
  retreat

검증을 통과하지 못한 candidate는 저장하지 않고 새로운 random seed로 다시
생성한다. rejection reason은 placement_error, floor_penetration,
self_collision, joint_limit, non_finite, no_bilateral_contact_grasp,
object_not_lifted 등으로 구분한다.

11. 현재 주의사항
----------------

- 실제 성능 평가는 최소 수십 개 episode와 충분한 ACT 학습 step이 필요하다.
- random initial pose에 따라 candidate trajectory가 collision 또는 joint-limit
  검증에서 탈락할 수 있으며, generator는 max-attempts 범위에서 자동 재시도한다.
- 기본 min-floor-clearance는 -0.008 m이다. 이는 floor와 contact하지 않도록 mask된
  아래쪽 fingertip collision proxy의 형상 범위를 고려한 값이다.
- frame-stride를 변경하면 LeRobot FPS도 변경된다. control-hz 50에서 stride 5는
  10 Hz, stride 10은 5 Hz이다. validate_lerobot_dataset.py의 --expected-fps도
  동일하게 설정해야 한다.
- 학습과 추론에서는 동일한 repo-id, dataset root, image resolution과 camera
  구성을 사용해야 한다.
- full 50-episode/20,000-step 학습은 아직 실행하지 않았으며, 구현과 smoke test
  수준의 전체 단계 호환성까지 검증된 상태이다.


12. 현재 완료 상태
-----------------

데이터 획득 -> LeRobot 변환 -> 데이터 검증 -> ACT 학습 -> MuJoCo 추론까지의
코드 경로가 모두 구성되었으며, 각 단계는 소규모 smoke test에서 실제 실행을
통과했다. red block의 강제 weld는 사용하지 않는다.
